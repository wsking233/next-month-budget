# Phase 4 本地保存与备份交付

## 实现范围

- 独立 LocalStorageRepository，首次读取并校验快照；用户账本与当前查看周期自动保存，刷新或关闭重开可恢复。
- 先计算与完整校验，再单键写入，成功后发布 Zustand 新状态。配额不足、权限拒绝、冲突或校验失败时操作不生效、旧账本不变，表单输入可修改重试。
- 严格版本 1 Schema 与账务校验：主键及名称去重、真实日期和周期顺序、引用、整数分及累计范围、账户内账单去重、分配总额、有效结算净额、成对调拨、审计状态及历史更正/撤销流水来源与冲销一致性。
- 设置页 JSON 下载、文件读取、导入预检、摘要和覆盖确认。恢复完整快照，不合并、不重复记账；取消/失败不改账本。
- 损坏或未知版本的本地文件保留原始内容并暂停写入；可下载原始存储、重新读取、有效备份恢复，或明确清空。无权限时须先恢复浏览器权限。
- storage 事件与写前旧值比较避免旧视图覆盖已知外部更新；用户重新读取后再编辑。非跨标签页事务，避免多标签页同时修改。
- 独立演示不持久化、不能作为用户备份导出；返回保留本地账本。清空需确认，失败不删除原数据。

## 手动验收

1. 从空账本创建周期、资金池、拨款和结算，观察已保存状态；刷新、关闭重开，检查余额、审计和查看周期一致。
2. 在设置导出 JSON，增加几项数据后选择该备份。检查摘要，取消应保持原账本；再次选择并确认覆盖，应恢复导出时的内容，再刷新核对。
3. 修改备份为损坏 JSON、未知版本、无效引用、分配不平或缺少调拨半边，导入均应报错且不改变已有账本。超过 2 MB 文件应在读取前拒绝。
4. 模拟存储配额错误后提交表单，检查原账本不变、输入保留、没有“操作成功”；恢复存储后重新提交可成功。恢复或清空同样不能在保存失败时生效。
5. 本地原文件损坏时应暂停写入，先下载原始存储留存；不得自动生成空账本覆盖。可从有效备份恢复或明确清空；未知版本行为相同。
6. 打开第二标签页后在第一页提交，第二页应提示重新读取，旧页不能覆盖新数据。避免两页同时提交。
7. 进入独立演示并修改，返回、刷新后用户账本不受影响，演示修改不保留。清空用户账本需确认并只清空当前账本。
8. 检查 375 / 768 / 1440px 设置页、覆盖弹窗、键盘操作和深浅色；JSON 文件只在本机下载/读取。

## 边界

本地数据不跨设备同步，清理站点数据、隐私模式或更换设备可能丢失，需定期备份。JSON 未加密，不上传，文件由用户妥善保管。结构和账务校验不是真实性认证，不能防止有意重写全部一致数据。

首版快照为版本 1，最大 2 MB；未知版本不自动迁移。Phase 3 没有持久化文件可迁移。主题仍只在内存中；未引入账号、后端、云数据库、预测统计或 Service Worker，不承诺离线首次访问。

直接在 main 提交并推送，自动触发现有 GitHub Pages 流水线；按用户约定不查询 Actions 状态 API。本阶段完成后等待 Phase 5 指令。
