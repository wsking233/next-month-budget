# 预算资金池业务规则

## 基本概念
- **预算拨款**：向分类预算赋予消费额度，不等于实际银行转账。
- **预算余额**：期初结余 + 本期拨款 + 调入 - 调出 - 已归属支出 ± 更正。
- **正余额**：可以跨期累计，不在月末自动失效。
- **负余额**：跨期保留；以后拨款优先抵扣，不能自动由其他资金池弥补。
- **计划储蓄**：预算收入减去计划消费拨款等规划项，是目标而非已经实现的现金存款。
- **实际净储蓄**：需要额外核对现金、负债和实际流入流出，不能用预算余额替代。

## 样例（可配置，不是硬编码）
实际月收入 20,000；计划储蓄 13,000；计划消费拨款 7,000。
资金池：日常 3,500、数码兴趣 2,000、不定期开支 1,500。
这些仅是启动样例，可随实际租房、收入变化调整。

## 账务不变量
1. 一笔已经确认的结算分配仅扣减一次预算。
2. 预算调拨必须一出一入，净变动为 0；需要明确记录。
3. 每张已确认结算单的分配合计等于被结算金额。
4. 金额以最小货币单位整数存储（人民币分），避免浮点误差。
5. 未分配或有争议账单不能伪装成完成结算。
6. 拨款、更正、结算、调拨都要可以追溯，避免直接覆写历史结果。
7. 历史账务变更需要使所有后续周期重新计算或以版本化方式正确调整。
8. 不允许把资金池余额直接展示为可提款的现金余额。

## 超支处理
数码余额 2,000，发生 4,000 预算扣减，余额 -2,000；下一期拨款 2,000 后余额为 0。
若用户决定从旅行池转 1,000，必须新建有原因的调拨流水，不允许静默自动转移。

## 结转策略
期末不执行“清零”；下期根据上一期最终余额和当期拨款滚动计算。
资金池允许停用，但必须先处理仍在余额中的金额和已绑定的未来安排。

## Phase 3 内存账本执行规则

- 周期按开始日排序且不可重叠。查看某周期时，只累计该周期及以前流水；后续拨款不提前进入当前余额。正负结转均由流水计算，不复制或清零余额。
- 每次操作由领域函数校验后返回新账本；无效输入、重复提交、资金池停用或金额溢出均不产生部分流水或审计记录。金额及累计余额必须保持安全整数分。
- 资金池名称不可重复。无流水资金池可直接停用；已有流水时须在所选周期清零，并处理该池后续周期净变动及有效账单分配。已冲销且净额归零的未来历史不作为未处理安排；停用保留历史，允许重新启用。新拨款、调拨和新结算分配不可指向停用池。
- 调拨允许来源出现负预算（不代表可透支银行账户），但必须填写来源、目标、正数金额、周期及原因，两池不得相同；同次调拨生成等额相反流水。
- 审计记录按操作顺序追加，保留操作时间、当时资料、金额/周期分配和原因。更正及撤销不删除历史流水，以冲销和新分配重新计算受影响及以后周期余额。
- 本阶段仅内存保存，刷新即丢失。演示账本为独立工作区，不注入、不覆盖用户账本。localStorage、导入导出与备份恢复留到 Phase 4。

## Phase 4 保存与恢复规则

- 用户账本通过独立 repository 写入 localStorage；每次变更先完整校验，再成功写入同一快照键，最后发布新 UI 状态。保存失败则本次业务操作不生效，内存、审计和原存储不改变，输入保留供重试。
- 初始化校验失败或存储无权限时暂停业务写入，不用空账本覆盖旧内容。有效备份恢复和清空均须用户明确确认；读取失败的原文件可另存。
- 备份包含完整账本、审计和当前周期。恢复是整体替换，不合并、不重放业务操作；需先通过字段、引用、金额、调拨成对、结算/冲销净额及历史审计校验，保存失败也不切换账本。
- 读取或导入未知版本时拒绝处理，首版不隐式迁移。演示账本不持久化，导入导出仅针对本地用户账本。
- 浏览器清理、隐私模式和设备迁移存在本地数据丢失风险；JSON 未加密且不上传，应定期导出并妥善保管。

## Phase 5 统计与规划口径

- 上期结转 + 当期预算拨款 − 当期有效结算 + 当期净调拨 = 当期期末预算余额。结算口径为现有结算与冲销流水的净额；更正历史后统计与后续结转一起重算。
- 拨款分布只以所选周期已录入的预算拨款为分母，不以净余额计算百分比，不将负余额伪装为资产占比。趋势按真实周期显示，最多六期；未建周期或未建资金池时不造数据。
- 只读模拟从所选周期余额出发：下一期余额 = 上期模拟余额 +（可选）该未来周期已有流水净变动 + 用户每期额外拨款假设 − 用户每期额外预算结算假设。手工假设默认为零、最多六期，不自动照搬收入或历史消费。
- 已有未来周期按实际顺序使用；超过已建周期时仅显示“模拟第 N 期”，不自动推定日期或新建周期。未分配账单、未来现金/收入/还款不自动纳入；额外假设叠加于已有流水，界面提醒避免重复填写。
- 模拟不写入 Zustand 账本、localStorage、审计或备份，不提供“应用到账本”按钮。离开页面、账本/周期变化或修改假设后需重新生成；预测不是实际预算或现金承诺。

## v0.8 收入与固定金额模板

用户于 2026-10-18 确认：固定金额模板，每次预览后手动确认；收入不足时提示调整，不自动缩减或跨池补足。

- 模板包含各池固定拨款和计划储蓄，保存/编辑不产生拨款，不改历史。复制所选周期净拨款仅填充表单，可选上期复制后切回目标周期应用。停用池不接收新拨款，表单明确提示排除情况。
- 每笔实际收入记录日期、人工归属周期、周期内唯一标识、金额及分配快照。支持同周期多笔收入，日期与归属周期独立，不推算发薪日。标识去首尾空白后防重，已撤销收入仍占用标识。
- 收入 = 本次关联拨款 + 计划储蓄 + 未分配金额；三项非负、整数分。计划储蓄是目标，未分配额不是现金储蓄。独立手工拨款不自动归属收入，也不自动从模板扣除，提交前须核对避免重复。
- 预览无持久化，确认后原子保存收入、各池拨款和审计；保存失败不产生部分记录，保留输入供重试。
- 修正采用先撤销原收入再以新标识重新登记。撤销追加 `income_reversal` 冲销关联拨款，保留原收入及原因，不撤销后续支出，也不代表银行退款。后续负余额照常结转。统计拨款包含原拨款及冲销净额，收入/储蓄指标只汇总有效收入。

## v0.9 还款独立规则

还款记录、撤销及账户维护不生成 BudgetEntry，不影响预算余额、结算及冲销。账单未分配、已结算或已撤销预算结算时均可登记实际还款。每笔正整数分，累计有效还款不超过当前账单总额。先还款后结算和先结算后还款等价。修改账单总额不能低于有效还款，已有有效还款不得更换原账户文字。


## v0.11 编辑与恢复保护

支持 Web Locks 的同源页面仅允许持锁页真实写入；等待页可只读查看和独立演示，不执行真实入账、恢复或清空。取得权限先重新读取快照。无 API 时继续保持版本冲突检查并要求单页编辑；锁失败暂停写入。恢复预览后若领域账本对象变化，需重新核对再确认；保存成功后才更新界面的规则不变。此版本不改变备份格式或财务计算。
