# v0.9 之后的开发计划

日期：2026-10-18。基线：v0.9.0；77 项单元/界面测试及96项浏览器检查已有通过证据，连续三周期综合验收已通过。测试结果引用现有交付记录，本次规划未重新执行应用测试。

状态：第一阶段按自动开发目标实现为 v0.10.0，交付记录见 `docs/27-v0.10-delivery.md`；后续阶段继续按验收与明确规则推进。沿用纯前端、本地数据、main 单分支及现有 Pages CI/CD。未来版本号为拟定目标；新业务规则未因列入计划而自动定案。

## 推荐顺序

| 优先级 | 阶段 | 交付目标 | 进入条件 |
| --- | --- | --- | --- |
| P0 | v0.10 日常操作效率 | 更快找到待办，减少重复输入，提高备份可见性 | 复用当前规则，可直接拆任务 |
| P0 | v1.0 正式版收口 | 完成真机体验、使用反馈修复及发布核对 | v0.10 验收通过，首版范围冻结 |
| P1 | 后续版本：大额消费预占 | 出账前看见已承诺额度，结算时不重复扣预算 | 先确定预占、核销、释放及跨期规则 |
| P2 | 后续版本：退款与账单调整 | 正确处理真实退款，区别于撤销错误记录 | 先确定退款归属、金额上限及还款关系 |
| 可选 | PWA / 离线 | 安装与资源离线访问 | 单独确定缓存、更新及旧版本写入策略 |

## 第一阶段：v0.10 日常操作效率

### 1. 账单与还款筛选

- 账单页增加独立的还款状态筛选：未记录、部分已还、已还清；与现有预算结算状态、账户及到期日期组合使用。
- 账户筛选支持稳定信用卡账户，兼顾尚未关联的旧账户文字；改名后仍能按同一账户查询。
- 提供匹配数量、无结果提示和完整重置。列表排序与到期提示保持明确日期口径。

验收：同一账单可以同时显示「待分配且已还清」或「已结算且未还」，组合筛选结果正确；查询、排序及重置不写账务或改变备份内容。

### 2. 收入与模板操作

- 提升历史收入查找能力，支持按周期、状态及标识检索；展示收入、关联拨款、计划储蓄和未分配金额。
- 模板提供清晰的当前金额预览，复制周期拨款时显示来源周期及其为净拨款的口径；停用池排除情况醒目提示。
- 还款表单可用当前未还金额填充金额输入；仍须用户填写日期、唯一标识并明确提交，不自动记账。

验收：取消、预览和填充不写入；收入不足、重复提交及超额还款继续被拦截；确认前账本若变化，提交按最新账本重新校验；失败保留输入。

### 3. 备份状态与恢复体验

- 展示上次生成导出文件的时间，以及此后是否有账务变更，帮助判断何时再次备份。
- 文案明确区分「生成导出文件」与「文件已实际下载并妥善保管」，不能声称已确认浏览器下载成功。
- 提醒仅在页面内展示，可关闭；账本导出、恢复和写入失败时仍可操作已有安全入口。
- 恢复预览清楚显示文件格式版本、记录数量及整体覆盖范围，继续要求明确确认。

验收：备份偏好或提示元数据写入失败不影响账本；演示操作不改变用户备份状态；未知/损坏文件、取消恢复、空间不足及旧标签页冲突均保全原数据。不因提示功能无必要升级账本格式。

### 交付要求

按新增行为补充领域/存储或浏览器检查，复用现有三浏览器、无障碍和财务守恒门禁。通过后单独发布 v0.10，不与下一阶段新账务规则混合。

## 第二阶段：v1.0 正式版收口

- 按 `docs/25-release-candidate-validation.md` 固定首版范围，逐项核对真实使用体验；v1.0 不代表所有历史 Draft PRD 条目均已实现。
- 在可获得的实际手机浏览器验证日期/金额输入、软键盘、弹窗滚动与焦点、长文本及文件导出/选择恢复；记录实际设备、浏览器版本和结果。无法取得的设备明确标为未验证，不用模拟结果代替。
- 用无敏感数据先走一遍建账、收入、跨期结算、分次还款、撤销和备份恢复；再收集用户实际使用时的困惑与缺陷。
- 修复影响金额、数据安全、关键操作及手机使用的问题；验证旧格式读取、失败不覆盖和多标签页冲突。
- 完善简短使用说明、版本升级说明及问题反馈模板；反馈不要求提交真实工资、卡号或完整敏感备份。

发布验收：范围明确，关键缺陷已解决，所需真机结果与已知限制可查，自动门禁通过；再标记 v1.0。实际体验确认不阻塞先做 v0.10。

## 第三阶段候选：大额消费预占

解决出账前尚未结算的大额消费没有反映在预算中的问题。先写规则及示例，再进入编码：

1. 预占是否只减少「可安排额度」，保持当前已结算预算余额定义不变？建议分别显示预算余额、预占额、可安排额度。
2. 一项预占能否拆到多个池/周期，金额是否可改，未完成部分是否跨期保留？
3. 账单分配如何显式关联预占、支持部分核销？核销必须与结算原子保存，不能既预占又重复扣减。
4. 取消预占、撤销结算、更正分配或停用资金池时，预占如何恢复或释放？

验收示例：预算余额1000元，预占600元，可安排400元；该消费出账并结算600元后，预算余额400元、预占0元，可安排仍为400元。例子是待确认方案，不能作为已批准规则实现。

新增实体需新格式版本、旧数据默认无预占、严格迁移及失败保全测试；只读预测必须明确是否纳入预占。

## 第四阶段候选：退款与账单调整

撤销错误记录已经实现，但真实退款是新的经济事项，须保留原消费及退款关联。

先确认退款发生在原期还是当期、是否退回原池、部分退款与累计上限、已还清账单产生退款如何呈现，以及与预占/结算更正如何防重复。银行退款和账务撤销不能共用一个含糊按钮。

验收至少覆盖跨期部分退款、重复退款、原账单修改及已还清后退款；预算、账单应还与实际还款各自核对。分期、费用、利息与超额还款不顺带实现。

## PWA 与其他候选

PWA 先确定安装需求、离线资源范围、缓存更新提示、旧页面读写兼容及回滚策略；缓存不能作为账本备份，也不等于后台到期通知。当前 v3 备份、本地保存和无银行/后端的边界继续有效。

加密备份、非信用卡支出、批量结算与多模板可待用户反馈后排序。任何服务端、登录、云同步或银行接入继续需要明确授权。

## 执行约定

只在 main 开发、验收及发布；保留追加审计、整数分、保存成功才更新界面。每阶段验收后单独提交、标记版本并推送，由既有 Actions 发布 Pages；日常不查询 Actions 状态 API。规划文档本身不升级应用版本。

本次推荐的下一个开发任务：v0.10 的「独立还款状态与稳定账户组合筛选」，随后完成收入/模板体验及备份状态提示。第一阶段无需再次确定已确认的收入和还款规则。
