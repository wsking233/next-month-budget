# v0.11 编辑安全收口计划与交付

日期：2026-10-18。规范基线：main / v0.10.0。沿用用户自主规划、实现、逐阶段发布的授权；不新增财务规则、后端、银行连接或 PWA。

## 选择这一阶段的原因

v0.10 已形成收入、预算、信用卡及备份闭环。此前多标签页保护依赖存储事件和写前版本比较，两页极短时间内同时检查、写入时仍可能互相覆盖。本阶段优先加固本地数据安全，不继续扩大未确认的产品范围。

## 实施与验收

1. 支持 Web Locks 时，同源页面争用同一个独占编辑锁，只有持锁页可执行真实账务、恢复或清空。等待页仍可查看快照、切换查看周期（不写存储）、导出和使用独立演示。
2. 编辑页关闭/刷新后自动释放锁；等待页取得锁后先重新读取最新快照，再允许写入。请求失败暂停写入，不静默降级。React StrictMode 清理会取消待处理请求、释放持锁，避免泄漏或误锁。
3. 不支持该 API 时维持原有版本冲突与存储事件保护，明确提示仅单标签页编辑。旧版页面不参与新锁，升级前应关闭旧页面并重新打开；锁不能阻止浏览器数据清理、开发者工具或不遵循协议的旧应用写入。
4. 恢复预览关联当时的领域账本对象；若之后重新读取或发生新账务，确认恢复时拒绝旧预览，需取消、重新选择并核对。仅查看周期不改变财务对象，不使预览失效。原始文件及旧账本保持不变。
5. 不更改领域模型及备份 schema，仍为 v3，继续严格读取 v1/v2。

## 验证结果

- `npm run check`：83 项单元/界面测试、ESLint、TypeScript、生产构建通过。
- 新增四项工作区测试：锁等待/失败下写入阻断、演示隔离、过期恢复预览、只读周期选择。
- 新增三项浏览器场景：跨标签页写入/清空/恢复阻断与接力、无 API 兼容、锁请求失败。
- `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:browser -- --workers=2`：全部 41 项 Chromium 生产构建回归通过，无跳过。现有门禁继续在 CI 运行 Chromium / Firefox / WebKit；本机没有 Firefox / WebKit 可执行文件，浏览器下载被环境网络策略拒绝，因此不将未运行结果写为通过。
- 375/768/1440px、深浅色、六页面 WCAG AA 自动检查继续沿用现有套件。自动引擎和视口不等于真机验证。

## 成熟度与边界

当前具备个人本地试用所需的核心闭环、迁移和失败保全，达到本轮“相对成熟可用”目标。正式 v1.0 仍按原计划等待实际手机日期/金额软键盘、文件保存选择和人工体验反馈，不伪造真机结果。退款、分期、预占、云同步和 PWA 仍不纳入。
