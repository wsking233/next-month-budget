# 决策记录与待确认问题

更新日期：2026-10-18

## 已确认方向
- 名称：下月再说（Next Month Budget，英文工作名）。
- 个人预算资金池管理，不以每日逐笔记账、投资理财或商业化为目标。
- 资金池允许正负余额跨期结转；任何跨池调拨须明确授权并留痕。
- 多张信用卡分别记录账单；区分账单日、还款日、预算归属周期。
- **平台方向已变更：标准 Web App 优先，使用 React + TypeScript，响应式布局同时服务桌面、平板和手机。**
- **停止原生 iOS / React Native / Expo 路线。** 旧平台工程、前端页面、路由、构建配置、专属计划已从主分支移除，历史可通过 Git 提交记录恢复。
- 领域逻辑保持平台无关，优先业务规则正确性及可测试性。
- Phase 4 已实现版本化 localStorage 自动保存及 JSON 备份恢复；Zustand 经 repository 提交，写入成功才更新状态，失败保全旧账本。演示账本隔离且不持久化。
- 首版只有浏览器本地数据：选择 localStorage 存放版本化账本快照，支持 JSON 导入/导出；不采用远程数据库、登录或云同步。PWA 是否启用尚未定案。
- 六阶段开发计划详见 `docs/13-web-development-roadmap.md`；Phase 1–6 路线图已交付，版本 0.6.0；新增业务规则继续区分已确认与待验证。

- 部署采用 GitHub Pages + GitHub Actions；仅保留 main 分支，直接开发、检查、发布。使用 Hash 路由支持静态托管子页面刷新，资源使用相对路径。

- 按用户约定，不在日常推送后查询 GitHub Actions 状态 API；仅发布异常时再排查。

- 本地格式版本 1；未知版本拒绝读取，不自动迁移。单文件不超过 2 MB；恢复为整体覆盖，二次确认后保存成功才应用。校验用于检测结构/账务损坏，不提供真实性认证。

- Phase 5 采用轻量 SVG 趋势与可访问金额明细，无需新增图表依赖；模拟额外拨款/结算默认零，可选择计入已有未来流水，不创建实际账务。
- 用户已授权自主按阶段完成后续任务，每阶段单独验收、提交和推送发布。

- Phase 6 引入 axe-core 自动审计与 Chromium / Firefox / WebKit 项目，修复对比度、可访问名称、焦点循环及窄屏长文本；部署需通过全部检查。WebKit 引擎测试不等于 Safari 真机认证。

## 临时假设（待验证）
- 发薪日作为预算周期起点（例：每月 10 日）。
- 账单默认归属还款日所在的工资周期，允许人工调整。
- 示例分类：日常、数码兴趣、不定期开支。
- 示例收入 20,000、计划储蓄 13,000、消费预算 7,000（非真实配置）。
- 同一账单可在多个预算周期之间拆分。
- 手动导出/恢复是首版必要能力。

## 关键待确认项
1. 不规律收入、多收入来源和额外两薪如何分配？
2. 出账前如何预占大额消费，避免预算可用额高估？
3. 退款、冲正、分期和部分还款的处理策略。
4. 透支提醒阈值；调拨、更正和撤销的首版执行边界已写入业务规则，其他例外继续待验证。
5. 非信用卡消费与信用卡账单怎样避免重复归集？
6. 备份为未加密 JSON，版本 1、Zod 与账务一致性校验已实现；未来加密及版本迁移策略仍待需求明确。
7. 浏览器本地数据丢失风险、离线资源缓存与未来可能的数据迁移如何安排？
8. 响应式交互细节、是否启用 PWA。

## 协作要求
产品规则、架构假设和已确定决策分开维护；不应将旧 Expo 实现误认为未来 Web 产品的约束。
