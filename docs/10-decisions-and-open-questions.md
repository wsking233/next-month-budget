# 决策记录与待确认问题

更新日期：2026-10-17

## 已确认方向
- 名称：下月再说（Next Month Budget，英文工作名）。
- 个人预算资金池管理，不以每日逐笔记账、投资理财或商业化为目标。
- 资金池允许正负余额跨期结转；任何跨池调拨须明确授权并留痕。
- 多张信用卡分别记录账单；区分账单日、还款日、预算归属周期。
- **平台方向已变更：标准 Web App 优先，使用 React + TypeScript，响应式布局同时服务桌面、平板和手机。**
- **停止原生 iOS / React Native / Expo 路线。** 旧平台工程、前端页面、路由、构建配置、专属计划已从主分支移除，历史可通过 Git 及归档分支恢复。
- 领域逻辑保持平台无关，优先业务规则正确性及可测试性。
- 当前仅保留业务领域模型、测试和业务规划文档；Web 工程待下一阶段搭建。
- 离线及可恢复性是产品需求；Web 端采用何种持久化、备份及可选 PWA 方案尚未定案。

## 临时假设（待验证）
- 发薪日作为预算周期起点（例：每月 10 日）。
- 账单默认归属还款日所在的工资周期，允许人工调整。
- 示例分类：日常、数码兴趣、不定期开支。
- 示例收入 20,000、计划储蓄 13,000、消费预算 7,000（非真实配置）。
- 同一账单可在多个预算周期之间拆分。
- 手动导出/恢复是首版必要能力。

## 关键待确认项
1. 不规律收入、多收入来源和额外两薪如何分配？
2. 出账前如何预占大额消费，避免预算可用额高估？
3. 退款、冲正、分期和部分还款的处理策略。
4. 透支提醒、跨池调拨、结算更正和撤销审计边界。
5. 非信用卡消费与信用卡账单怎样避免重复归集？
6. 备份数据隐私、版本与完整性校验方案。
7. Web 的本地持久化、离线与多设备同步是否需要分阶段实现？
8. 响应式信息架构、技术依赖、部署环境及是否启用 PWA。

## 协作要求
产品规则、架构假设和已确定决策分开维护；不应将旧 Expo 实现误认为未来 Web 产品的约束。
