# 产品需求文档 PRD｜初稿

状态：Draft（待实际账单验证）。平台方向：React + TypeScript 响应式 Web App。

## 核心使用流程
1. 初始化：设置发薪周期、默认收入、目标储蓄、消费拨款及资金池。
2. 发薪：确认实际收入，生成当期资金池拨款和计划储蓄。
3. 出账：选择信用卡、输入账单金额、日期和对应还款日。
4. 分类：将账单总金额拆分给多个资金池，必要时指定不同预算周期。
5. 确认：校验拆分合计与总额一致，生成可追溯预算流水。
6. 复盘：显示资金池余额、负余额、未来拨款抵扣、预算目标与还款日程。

## P0（首版必须）
- 自定义预算周期起始日，支持非自然月。
- 资金池创建、编辑、停用；设置每期拨款金额。
- 正负余额跨期滚存，不自动归零。
- 账单登记与分类拆分；多信用卡不同账单日/还款日。
- 用户可调整预算归属周期；默认规则见结算文档。
- 分配金额合计必须等于账单金额。
- 手工预算调拨、来源去向明确、保留操作记录。
- 账单编辑、更正、撤销与防重复结算。
- 区分预算可用余额和真实现金/信用卡负债。
- 本地保存、手动备份和恢复，离线可用目标需在 Web 环境验证。
- 概览、资金池、账单结算、未来预算及历史记录等核心功能。
- 界面布局适应手机、平板和桌面浏览器。

## P1（验证后）
- 未来预算预测与年度储蓄计划。
- 待还账单提醒（具体 Web 可用能力待评估）。
- 批量结算、结算模板和上期快速复用。
- 月度复盘及超支原因记录。

## 首版不做
- 银行 API 自动同步、逐笔自动抓取、投资理财。
- 多人账户、家庭管控、商业化收费。
- AI 账单识别、复杂多级类别和云端账户系统。
- 原生 iOS、React Native、Expo 专用客户端。

## 关键交互要求
- 概览显示当前周期、可用预算、账单状态及结算入口。
- 账单管理提供已结算记录、总额拆分、差额核对与归属周期选择。
- 低频管理包括周期、资金池、拨款、操作记录、备份与恢复。
- 导航按屏幕宽度适配，不预设 iOS 底部标签栏或原生控件。

## 业务验收场景
1. 数码资金池余额 2,000，扣 4,000 后为 -2,000；下期拨 2,000 后为 0。
2. 两卡账单跨不同还款周期分别计算预算归属，不双重扣除。
3. 单张 6,200 账单分配 2,800 + 2,100 + 900 + 400，全额匹配。
4. 调拨 1,000 时两边同步变动，预算总额不变。
5. 同一已确认账单再次导入或保存，不能重复扣减。
6. 更正历史结算后未来余额可重算且可追溯。

## 当前阶段实现边界

Phase 4 已在首版账务闭环上加入本地自动保存和 JSON 备份恢复，刷新/关闭重开恢复同一浏览器账本。维护、更正、撤销及停用规则见业务规则与结算文档。收入与储蓄计划、还款记录、离线资源缓存尚未完成，不应将所有 P0 需求视为已完成。数据清理或换设备可能丢失账本，需定期备份。

Phase 5 已加入预算统计、多周期对比和未来拨款的只读模拟。模拟不等于收入或储蓄规划，不创建真实流水；详细计算口径见预算业务规则。

Phase 6 已完成路线图内质量及静态部署验收。该里程碑不等于 Draft PRD 中全部 P0/P1 能力：收入/储蓄规则、还款记账、退款分期、提醒、批量操作与 PWA 继续按明确需求另行推进。

## v0.8 范围补充

按确认规则实现固定金额模板、实际收入记录、预览确认拨款、收入防重及撤销冲销。收入不足须人工调整；计划储蓄不等于实际现金储蓄。现有手工拨款继续独立，收入不自动触发现金流核对。还款、退款分期及 PWA 仍未实现。
