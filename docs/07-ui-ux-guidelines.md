# UI/UX 原则

## 品牌
中文名：下月再说；英文工作名：Next Month；仓库：next-month-budget。
语气：轻松、有一点幽默，但财务结果必须严肃、透明、可信。
候选标语：想花就花，有数就行。／这个月的快乐，下个月也要负责。
正式上架前核查名称与商标冲突。

## 主要体验准则
- 移动端优先，避免把 Web 数据后台界面缩成手机尺寸。
- **低频使用、低录入成本、高预算可见性**。
- 不强迫逐笔消费、二级分类或多层导航。
- 首页优先展示资金池剩余、负数、待结算账单和储蓄目标。
- 日常三类场景：发薪确认、账单结算、购物前查看额度。
- 财务操作可预览变更后余额；确认时突出差额与影响周期。
- 正负余额同时使用文字和数字明确表示，不仅依赖颜色。
- 金额输入默认人民币，清晰展示小数位、千分位和预算周期。
- 编辑已结算数据应走更正流程，不能悄悄覆盖。

## 竞品感受与取舍
Goodbudget 的信封预算很成熟，但用户认为分类颗粒度过细、移动端操作更接近传统Web流程，不符合本项目极简的集中结算体验。产品不以模仿其所有功能为目标。
Actual Budget 可以参考开源领域规则、预算逻辑；YNAB 可学习信用卡还款与预算消费的区分；其他产品仅作为参考。

## 设计验证问题
- 一张 6,200 元账单能否在少量操作中完成四类分配？
- 负数结转是否一眼可读？
- 划拨/调拨/结算的操作是否容易误混？
- 多卡不同到期日，用户能否不费力找到正确预算月份？
