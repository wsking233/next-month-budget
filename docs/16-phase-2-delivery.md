# Phase 2 业务页面与交互原型

## 实现范围

- 六个业务原型页面：概览、资金池、账单、预算计划、历史记录、设置。
- 默认空状态，用户主动加载独立脱敏样例；明确显示演示模式、刷新即清空、不录入真实数据。
- 创建周期、创建资金池、独立拨款、登记账单、逐行按资金池和周期拆分、实时差额、二次核对确认。
- 演示预算余额、账单分配状态、操作记录随内存操作更新；结算不会显示为已还款。
- 历史记录类型筛选和搜索；桌面表格、移动端卡片；可交互偏好预览、禁用未实现的备份入口。
- 弹窗可滚动、键盘焦点约束、Escape 关闭、关闭后焦点返回；清空或重载现有演示需确认。
- 原领域模型不变；演示模块位于 `src/prototype/`，未引入正式账务持久化、后端或账号。

## 文件清单

- `src/prototype/model.ts`、`store.tsx`：独立样例和临时界面状态。
- `src/prototype/ui.tsx`、`forms.tsx`、`PrototypePage.tsx`、`ActivityList.tsx`：控件、表单和六个页面。
- `src/App.tsx`、`src/components/AppLayout.tsx`、`src/index.css`：路由、演示提示和响应式样式；移除旧空页面。
- `src/prototype/model.test.ts`、`tests/browser/prototype.spec.ts`：金额精度、隔离、负余额和真实浏览器交互验收。
- `vitest.config.ts`、`playwright.config.ts`：演示纯函数测试发现、可选系统 Chromium 路径。
- README、AGENTS、决策记录、路线图与本交付文档。

## 验证结果

- `npm run check` 通过：ESLint、TypeScript、27 项测试（原领域与界面 13 项 + 演示模型 14 项）及 Vite 生产构建。
- `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:browser`：7 项通过，覆盖三个屏幕宽度、导航/主题、无横向溢出、空账本主流程、小数差额、跨期拆分、确认、记录筛选、刷新隔离及 Escape/焦点返回。
- 本地使用系统 Chromium 154；CI 保持 Playwright 配套 Chromium，不依赖该本地路径。已查看手机概览、手机拆分弹窗及桌面历史记录截图。
- GitHub Actions 的部署结果以远程执行为准，本地测试通过不等同于已确认线上部署成功。

## 手动验收

1. 打开部署地址：初次应为空白演示，不自动注入财务样例。
2. 加载演示数据，依次访问六页，检查 375 / 768 / 1440px 和深浅色。
3. 在账单页拆分 A 卡：第一行 2000.01 元；第二行 599.98 元时不能核对，改为 599.99 元后可核对。第二行改选十一月预算，检查确认文字及最终归属。
4. 确认模拟结算后，检查账单为「演示已结算」，仍提示还款未记录；概览、资金池、历史记录同步更新。
5. 清空演示，先创建周期，再创建资金池：余额应为零。单独拨款后才增加预算。登记并结算超过拨款的账单，检查负余额。
6. 输入三位小数或重复的账户/账单标识，检查错误与输入保留；取消和 Escape 关闭弹窗不改变演示状态。
7. 搜索及筛选记录；桌面显示表格，手机显示卡片。设置偏好仅预览，不修改账务，备份恢复尚未开放。
8. 刷新页面，确认演示数据清空；重载或清空已有演示先出现确认。

## 边界与后续

当前仅为 Phase 2 UI 原型，金额校验和余额变化用于演示，不是正式领域账本或审计实现。演示累计余额包含所有样例周期的操作，不冒充所选周期余额。默认按还款日建议归属仍是待验证假设，可逐行手动调整。

领域闭环、完整撤销/更正、调拨、编辑停用在 Phase 3；正式状态管理、localStorage 和 JSON 备份在 Phase 4。未承诺离线缓存或跨设备同步。本阶段完成后等待视觉与交互验收，不自动进入后续阶段。
