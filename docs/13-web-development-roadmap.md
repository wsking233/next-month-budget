# Web App 分阶段开发计划

更新时间：2026-10-17。状态：**Phase 1–6 已完成，当前版本 0.6.0**。

## 目标和范围
构建纯前端 React Web App，使用响应式布局兼容手机、平板与桌面浏览器。首版仅在当前浏览器本地保存数据；**不接入后端、数据库服务、登录、云同步、Expo 或原生 iOS**。保留现有纯 TypeScript 预算领域模型及测试。

## 技术约定
- React + TypeScript + Vite；React Router 负责路由。
- Tailwind CSS + shadcn/ui 构建 UI；Zustand 管理界面/业务状态。
- localStorage 存储版本化 JSON 快照，通过独立 repository 接口访问；不把它称为数据库。以后数据体积或事务需求上升，再评估 IndexedDB。
- Vitest + Testing Library；Recharts 只在统计阶段引入，Zod 主要用于数据验证。
- 金额用整数分存储、人民币元显示；领域计算与 UI、存储解耦。
- 不在生产模式自动注入 Mock 数据；演示数据与真实账本明确隔离。
- 本地数据不跨浏览器、设备同步，清除站点数据可能永久丢失；备份恢复完成前不能宣称适合长期保存真实财务数据。
- 不承诺无网络首次访问或离线静态资源缓存：PWA/Service Worker 单独评估。

## 推荐信息架构
六个功能区域：概览、资金池、账单、预算计划、历史记录、设置。桌面优先侧边栏，移动端紧凑导航（低频页面可收纳至“更多”）。同一业务组件随宽度适配，不维护两套独立产品。
核心路径：创建周期 → 创建资金池 → 拨款 → 登记账单 → 按资金池/周期拆分 → 核对确认 → 余额与审计结果。创建、拨款、结算为独立动作。

## Phase 1 — 基础工程和响应式布局
工作：
1. 初始化 Vite + React + TypeScript、React Router、Tailwind、shadcn/ui；配置 TypeScript、ESLint、Vitest、Testing Library。
2. 保留 `src/domain/budget.ts` 和原有领域测试，使其继续通过。
3. 建立 AppLayout、统一设计 token、深浅色主题、响应式导航与 404 页面。
4. 增加概览、资金池、账单、预算计划、历史记录、设置六个空页面；只做页面骨架，不加入业务 Mock 和持久化。
5. 编写 README 的安装、运行、测试、构建步骤。
验收：`npm install`、`npm run dev`、`npm run build`、`npm run test` 和 TypeScript 检查通过；375/768/1440px 均正常；路由可达、无横向溢出、领域测试未回归。
**本阶段完成即停止，不提前进行 Phase 2。**

## Phase 2 — 业务页面与交互原型
工作：独立的脱敏 Mock 数据模块；实现六个页面的内容，以及业务卡片、列表/表格、金额及日期输入、表单、弹窗/抽屉、空状态、核对差额与手机表格转卡片。表单可交互，但 Mock 操作不得冒充真实入账或长期保存。
验收：主流程可用 Mock 完整演示，明确展示演示状态；桌面/平板/手机的入口、表单与布局可检查。此阶段以界面和操作路径验收为主。

## Phase 3 — 接入领域模型与业务闭环
工作：界面接入 `src/domain/budget.ts`；实现周期、资金池、拨款、账单登记/结算、资金池调拨、撤销、更正、余额计算和审计记录；界面展示真实内存账本，错误时不破坏原状态。遇到现有领域模型暂未支持的业务能力，先补充测试并更新业务文档，不用 UI 绕过规则。
验收：从空账本能走通完整链路；负余额跨期、分配合计、调拨守恒、防重复、更正撤销及审计测试通过。**此时尚无持久化，必须提示刷新即丢失。**

## Phase 4 — 浏览器本地存储与备份
工作：实现独立 `LocalStorageRepository` 与 Zustand 接口；版本化快照、初始化读取、变更保存、失败提示；JSON 导出/导入、Schema 与账务一致性校验、覆盖二次确认；错误文件不得覆盖原数据。保持业务操作和存储失败状态可解释。敏感数据不上传、不写入日志。
验收：刷新、关闭重开数据不丢；导出/恢复结果一致；损坏文件、版本不兼容、配额不足等情况给出反馈并保全旧账本；清空数据需确认。注明浏览器数据清理/隐私模式/换设备的风险。

## Phase 5 — 统计和预算规划
工作：复用同一领域账本，加入资金池余额、结转趋势、预算分布、多周期对比、未来拨款预测（只读模拟）；按需引入 Recharts。预测与实际账务严格分离，不把尚未确认的财务假设自动应用到真实账本。
验收：图表总额与账本一致，负数正确；空数据不展示虚假结果；预测绝不生成实际流水。涉及尚未确定的预测规则先记录假设并验收。

## Phase 6 — 质量与静态部署准备
工作：关键端到端流程、组件和领域回归；无障碍及键盘操作、深浅色、触摸交互、输入与错误状态；兼容常见手机/桌面浏览器；可构建为普通静态站点。明确本地数据风险、备份方式和部署配置。
验收：关键流程稳定、构建与测试通过，部署后不需要后端；不依赖原生框架。PWA 不在默认范围内，若增加需另行立项。

## 阶段里程碑
- **A：前端原型** = Phase 1 + Phase 2；先由人验收视觉、导航、表单与移动端体验。
- **B：可试用 MVP** = Phase 3 + Phase 4；只有备份与恢复通过后再投入长期个人数据。
- **C：可发布 Web 产品** = Phase 5 + Phase 6。

## Codex 执行与交付规则
用户现已授权自主完成剩余阶段；依次实施并独立验收、提交、发布每个 Phase。开始前阅读 `README.md`、`AGENTS.md`、本计划、PRD、预算业务规则、信用卡结算和数据模型；不得引入被删除的 iOS/Expo 技术。
