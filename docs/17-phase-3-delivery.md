# Phase 3 内存账务闭环交付

## 已实现范围

- 周期与资金池创建、独立预算拨款；所有 UI 操作通过纯 TypeScript 领域函数提交。
- 所选周期及此前流水累计余额；上期结转、本期净变动、负余额抵扣；未来拨款不提前计入当前余额。
- 账单登记、账户内去重、跨资金池/周期拆分与差额核对、二次确认、防重复结算。
- 显式调拨：同周期的一出一入流水，来源目标不同，金额为正，原因必填；不会自动补平超支。
- 账单分配更正、撤销、资料修改及重新结算。冲销与替换一次提交，多次修改后仍只扣减当前有效分配。
- 资金池重命名、停用与重新启用；停用前处理所选周期余额及未来流水，保留历史。
- 审计按操作顺序追加：时间、当时资料与分配、原因；桌面表格/手机卡片，可按操作筛选、按内容和原因搜索。
- Zustand 分别管理用户内存账本与独立演示工作区；查看演示和返回不会覆盖用户数据，重载样例只替换演示。
- 全页明确提示：尚未保存，刷新/关闭即丢失。没有 localStorage、后端、登录或云同步。

## 手动验收

1. 默认空账本，先建两个相邻周期，再建两个资金池，检查创建行为不自动拨款。
2. 一期拨款 100.01 元，二期拨款 20 元；查看一期只含 100.01 元。登记并一期结算 120.01 元：一期余额 -20 元，二期结转并拨款后为零。
3. 在账单中更正资金池或周期，填写原因，核对后确认。检查原周期与以后余额实时重算，历史中有原、新分配。
4. 撤销结算，填写原因，确认余额恢复；修改原账单总额或资料后重新结算，检查只扣新总额。已撤销记录继续占用账户内去重标识，不能另建重复账单。
5. 在一期或二期显式调拨，来源与目标相同时须失败并保留输入；成功后一出一入、总预算不变。原因可在历史中搜索。
6. 非零余额或有未来流水的资金池不能停用；处理余额及未来安排后可停用，新操作的可选池中不再出现，历史不删除。
7. 查看独立演示、进行操作、返回内存账本，确认原数据保留；重载演示与清空当前工作区需确认，刷新后全部清空。
8. 在 375 / 768 / 1440px 检查六页、表单、深浅主题、键盘 Escape、焦点恢复及无横向溢出。

## 边界与后续

当前不适合长期保存个人数据，下一阶段才实现版本化 localStorage、JSON 校验导入导出、保存失败处理与备份恢复。未引入还款记账、退款分期、储蓄规划、预测统计或离线缓存。账户目前使用用户输入的稳定名称作为标识，同一账户应保持一致。

UI 为每次输入设置一亿元上限；领域金额、累计预算和账单总额均须保持安全整数分。更正撤销采用追加冲销，审计不覆写。已结算总额修改必须先撤销，未结算/已撤销账单修改后回到待分配，再核对结算。

直接在 main 提交，推送触发现有 GitHub Pages 流水线。按用户约定，不查询 GitHub Actions 状态 API；实际发布结果以用户在 Pages 上验收为准。本阶段完成后不自动进入 Phase 4。
